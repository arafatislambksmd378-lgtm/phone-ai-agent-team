# GitHub Execution Architecture
Per task: validate project→repo binding → create task branch `agent/<project>/<task>` from default branch (Git Database/refs API) → agents produce file changes → Contents API commits (one commit per agent, author = agent id for attribution) → verification (compare API diff + Actions/checks status) → PR via Pulls API with task id, agent summary, test results → merge only after single-use approval consumed. Parallel tasks use distinct branches; integration is via PR merge, never force-push. No token → every remote call returns `{ok:false,error:'GITHUB_TOKEN not configured'}`; nothing is simulated.
