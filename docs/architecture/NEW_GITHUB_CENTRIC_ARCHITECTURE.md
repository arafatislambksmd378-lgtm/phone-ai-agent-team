# New GitHub-Centric Architecture
Layers: Android app / Telegram → HTTPS JSON API (`integrations/api`, stdlib, bearer token) → OrchestratorEngine (unchanged brain: planner/DAG/handoffs/approvals/scheduler) → GitHubExecutionService → GitHub REST client (per-project repo) + optional local git worker. Every task payload carries `project_id`+`repo_full_name`; executor re-validates binding against `project_repositories` before any call (Test 15). Termux scripts remain optional diagnostics, never required. Execution workers are stateless, single-worker default; heavy builds run in GitHub Actions (`.github/workflows/android.yml`), not on-device.
